# gatygo

[English](README.md) · **Русский**

VPN-клиент для роутеров OpenWrt. Вставьте ссылку на подписку от VPN-провайдера, выберите
страну, и вся домашняя сеть пойдёт через туннель. Настраивать каждое устройство не нужно.

gatygo принимает **подписку в формате Xray-JSON** (список готовых конфигов xray, по одному на
страну или профиль), запускает xray с выбранным и прозрачно проксирует LAN через nftables
tproxy. Всё управляется с одной страницы LuCI; настройки и лог находятся за шестерёнкой.

Интерфейс gatygo на английском, поэтому названия разделов и кнопок ниже даны так, как они
выглядят на экране.

## Что умеет

- Скачивает подписку по расписанию и проверяет каждый новый конфиг командой `xray run -test`,
  прежде чем его применить. Неудачное обновление не трогает рабочий конфиг.
- Показывает каждый профиль подписки кнопкой со временем отклика (TCP-соединение с роутера до
  самого быстрого сервера профиля).
- Проверяет, что привычные сервисы открываются через туннель (проверка идёт через xray тем же
  путём, что и трафик LAN).
- Перенаправляет DNS домашней сети в xray, не трогает трафик самого роутера, пока туннель
  поднят, отбрасывает IPv6-трафик LAN в интернет (он пошёл бы мимо туннеля), а при остановке
  всё возвращает как было.
- Берёт маршрутизацию, балансировщик и geo-файлы, указанные в подписке. Своих правил
  маршрутизации и списков серверов у gatygo нет.
- Объясняет простыми словами, что пошло не так: подписка истекла, достигнут лимит устройств,
  сервер не узнал клиента и так далее.
- Не даёт xray исчерпать память роутера: каждое открытое соединение стоит ему 50–70 КБ, поэтому
  одно устройство (например, торрент-клиент) держит через VPN не больше 600 соединений
  одновременно, а весь дом не больше 1000; новые сверх лимита отклоняются, уже открытые
  остаются. Оба числа настраиваются (Advanced → Settings).
- Если xray остановился насовсем (например, роутеру не хватило памяти), страница говорит, когда
  и почему. Что в это время получает домашняя сеть, задаётся в настройках: либо интернета нет,
  пока VPN не вернётся, чтобы ничего не шло в обход (по умолчанию), либо работает обычный
  интернет.

## Требования

- OpenWrt 25.12 (пакеты apk, firewall4/nftables).
- Около 40 МБ свободного места на overlay: скрипты gatygo маленькие, ядро xray весит 35 МБ.
- 256 МБ ОЗУ: в простое xray занимает 40–60 МБ в зависимости от подписки и ещё около 70 МБ,
  когда дом использует все соединения, которые разрешают лимиты.
- Подписка, которая отвечает в формате Xray-JSON. Некоторые панели провайдеров отдают его только
  клиентам, которых узнают по User-Agent: имя, которым представляется gatygo, задаётся в
  настройках (Advanced → Settings).

## Установка

На роутере:

```sh
wget -qO- https://raw.githubusercontent.com/id-filatov/gatygo/main/install.sh | sh
```

(`wget` в стоковом образе — это uclient-fetch; `curl` там пока нет.)

Сначала скрипт проверяет роутер и ничего не ставит, пока не пройдены все проверки: что это
OpenWrt 25.12, что те же правила не занимает другой пакет прозрачного прокси, что фиды
действительно отдают всё, что нужно gatygo (`jq`, `curl`, `ca-bundle`, `unzip`, `ip-full`,
`kmod-nft-tproxy`, `kmod-nft-connlimit`), что на overlay хватает места, что dnsmasq работает и
что XTLS собирает xray под эту архитектуру. Остальное в стоковом образе уже есть. Затем скрипт
ставит оба пакета последнего релиза, apk подтягивает зависимости, а закреплённое ядро xray
скачивается и проверяется, так что скачать остаётся только саму подписку. Ничего не включается,
подписка не записывается.

Обычно не проходит только образ, собранный вручную, и скрипт говорит об этом сразу, а не даёт
apk оборваться на полпути: модули ядра берутся из фида одной конкретной сборки ядра, а на
downloads.openwrt.org нет модулей для ядра, которое собирали не там. Добавьте в образ
`kmod-nft-tproxy kmod-nft-connlimit jq curl ca-bundle unzip ip-full` и запустите скрипт снова.

`install.sh --version v20260918.1851` ставит указанный релиз вместо последнего, а
`install.sh gatygo-*.apk luci-app-gatygo-*.apk` ставит локальные файлы, ничего не скачивая.

Вручную: скачайте `gatygo-<версия>.apk` и `luci-app-gatygo-<версия>.apk` из
[последнего релиза](https://github.com/id-filatov/gatygo/releases/latest), скопируйте их на
роутер и установите:

```sh
scp -O gatygo-*.apk luci-app-gatygo-*.apk root@192.168.1.1:/tmp/
ssh root@192.168.1.1 'apk add --allow-untrusted /tmp/gatygo-*.apk /tmp/luci-app-gatygo-*.apk'
```

Затем откройте в LuCI **Services → gatygo**, вставьте ссылку на подписку и нажмите **Connect**.
Подписка приносит конфиг, список стран и geo-файлы. Ядро xray уже на месте, если ставили
скриптом, иначе оно скачивается при первом запуске.

Чтобы обновиться, запустите скрипт ещё раз (`/etc/config/gatygo` сохраняется). Чтобы убрать
подписку, но оставить gatygo, нажмите **Delete** рядом со ссылкой в Advanced → Settings (или
выполните `gatygo forget`): VPN остановится, всё, что принесла подписка, сотрётся, настройки
вернутся к значениям по умолчанию. Чтобы удалить gatygo: `apk del luci-app-gatygo gatygo` (DNS и
файрвол роутера возвращаются как были, ядро удаляется; `/etc/gatygo` и `/etc/config/gatygo`
остаются, пока вы их не удалите).

## Ядро xray

gatygo не использует пакет `xray-core` из фида. Каждый релиз gatygo закрепляет один релиз
[XTLS/Xray-core](https://github.com/XTLS/Xray-core) вместе с SHA256 его архива для каждой
архитектуры (`gatygo/files/lib/core.pin`). Роутер скачивает архив для своей архитектуры,
сверяет SHA256, распаковывает только бинарник в `/usr/lib/gatygo/core` и пробует его запустить,
прежде чем заменить текущий. Пока хеш не совпал, ничего не распаковывается и не запускается.
Новое ядро приходит только с новым релизом gatygo, отдельного обновления ядра нет.

Без доступа к GitHub первый запуск не удастся, и страница об этом скажет; уже установленное ядро
продолжает работать.

## Командная строка

```
gatygo start|stop|restart        управление сервисом
gatygo connect <url>             первый запуск: сохранить ссылку, включить и запустить
gatygo forget                    убрать подписку: остановить, стереть всё, что она принесла, вернуть настройки
gatygo update                    обновить подписку сейчас
gatygo select <profile>          переключиться на профиль и применить его
gatygo status                    JSON: состояние, профиль, данные подписки, последний результат
gatygo check [fresh]             JSON: открываются ли привычные сервисы через туннель
gatygo ping [kept]               JSON: время отклика каждого профиля
gatygo nodes                     JSON: outbound'ы с выбором балансировщика и трафиком
gatygo log [N]                   последние N строк xray и gatygo из системного лога
```

Настройки лежат в `/etc/config/gatygo`, состояние в `/etc/gatygo` (сохраняется при sysupgrade),
логи в системном логе (`logread -e gatygo`, `logread -e xray`).

## Что где слушает

- Входы tproxy (12345) и DNS (5353) принимают перенаправленный трафик LAN.
- API xray (10085) и SOCKS-вход для проверки сервисов (10808) слушают только `127.0.0.1`.
  SOCKS-вход требует пароль, который создаётся на роутере и хранится в `/etc/gatygo` (права
  0600); API отдаёт статистику и состояние балансировщика, но не outbound'ы.
- Подписку, конфиг и секреты может читать только root. Ссылка на подписку, user id и hardware
  id никогда не попадают в лог.

## Разработка

```sh
tests/run.sh                     # юнит-тесты (POSIX sh в Docker: busybox ash, jq, закреплённый xray)
tests/run.sh test_core.sh        # один файл
tools/build-apk.sh               # собрать оба .apk в контейнере OpenWrt SDK
tests/vm/run.sh [gatygo.apk]     # сквозные тесты на VM с OpenWrt (см. заголовок скрипта)
tools/pin-core.sh v26.9.9        # закрепить другой релиз xray: core.pin и тестовый образ
tools/release.sh                 # выпустить релиз из main; CI соберёт и приложит пакеты
```

Скрипты написаны на POSIX sh для busybox ash. У `jq` в OpenWrt нет регулярных выражений, `curl`
там в урезанной сборке, и образ для юнит-тестов урезан так же. Тестовые фикстуры синтетические
(`tools/gen-fixture.py`, `tools/gen-geodat.py`).
